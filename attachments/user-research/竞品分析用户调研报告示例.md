# 竞品分析：用户访谈提纲与阶段性总结

> 本文保留早期访谈提纲与阶段性总结。最新完整报告见：[亚马逊精品运营用户调研报告](用户调研报告-亚马逊精品运营-20260914.md)。

适用对象：亚马逊日本站精品运营。依据当前分享、竞品跟踪截图及用户调研草稿整理。总结属于单次访谈的阶段记录，尚未经过其他运营、原始材料或实测交叉验证。

## 先看你的草稿：建议补这三处

你的顺序可以保留：工作全貌 → 耗时任务 → 具体流程 → 改进机会 → 自有产品是否承接。需要补的是中间的证据。

| 草稿中的位置 | 建议调整 | 原因 |
| --- | --- | --- |
| “存在 AI 提效的空间，因为……现在是人肉做” | 标为待验证假设，补问：用了现有工具之后，剩下哪一步最费时、最容易出错？ | 手工操作提示了机会，但不能直接说明需要 AI；也可能通过现有工具配置、字段匹配或模板解决。 |
| “人工怎么思考和合成报告：xxx” | 作为本次访谈的中心。让她拿一份报告，逐项解释：用了什么数据、做了什么判断、最后促成什么动作。 | 这里才能看出业务经验如何发挥作用，以及产品需要帮到哪一步。 |
| “我们自己的产品有没有相关能力？” | 保留到案例还原之后；用同一份材料试做，再区分已有能力、配置问题和新增需求。 | 产品能生成类似内容，不等于能完成她的任务。要看她实际补了什么、改了什么、是否愿意用于工作。 |

背景栏建议补齐：负责品类、本人职责、运营团队人数、自家 SKU 数、跟踪竞品数、报告接收人。公司规模与 Listing 链接保留。现场记录时，把受访者事实、你的业务理解、待验证假设分开写。

## 一、访谈提纲

**访谈目的：**还原一条竞品信息如何经过采集、整理、比较和判断，最终影响自家产品的运营动作；确认已有工具解决了什么，剩余时间与返工发生在哪里。

建议先用 40–50 分钟还原真实工作：背景约 5 分钟、案例约 25 分钟、困难与优先级约 10 分钟、核对理解约 5 分钟。自有产品演示另留时间，放在案例访谈之后。老师重点示范如何追问事实、证据和判断依据。

### 现场优先问这三个问题

1. 最近一次你因为竞品信息，决定修改或维持自家图片、卖点、价格或促销，具体是什么事？能从当时看到的第一条信息开始讲吗？
2. 这次用了卖家精灵、八爪鱼之后，你还亲手做了哪些步骤？哪一步花的时间最多？
3. 能展示一下原始资料、你最后写进报告的结论，以及交给美工或用于执行的内容吗？它们之间是怎样对应的？

### 完整提纲

| 环节 | 主问题 | 根据回答追问 | 希望听清楚什么 |
| --- | --- | --- | --- |
| 1. 工作量与口径 | 最近一个完整工作日，你做了哪些竞品相关工作？ | 每天约 2 小时是使用八爪鱼之前还是现在？包含跟踪、专题分析、写报告和沟通中的哪些部分？负责多少自家 SKU、实际跟踪多少竞品？ | 当前基线、任务频率与工作量。 |
| 2. 选择一次经历 | 请讲最近一次竞品信息影响了你运营决定的例子。 | 当时什么产品、什么时间、为什么开始查？最后采取了什么动作，或者为什么保持不动？ | 一次真实任务的触发点与终点。 |
| 3. 竞品如何选 | 这次你怎样从候选产品中选出要比较的竞品？ | 你说的“相似”具体指什么？自家 SKU 与竞品 ASIN 如何对应？什么时候加入或移除竞品？榜单之外还会关注谁？ | 竞品选择规则、比较范围与更新方式。 |
| 4. 数据怎样来 | 从开始查资料到拿到可用信息，你具体做了哪些操作？ | 卖家精灵、八爪鱼分别提供什么？草稿中的 H10 是否也在实际使用？哪些字段能直接用，哪些要补或核对？工具减少的是哪一步？还有什么拿不到？ | 工具分工、数据缺口及人工校验。 |
| 5. 报告怎样形成 | 能用这次原始资料，演示你怎样把它整理进市场报告吗？ | 哪些内容删除、补充、合并？怎样与自家产品对齐？价格、促销、规格和时间不同的时候怎样比较？报告给谁用？对方实际用了哪部分？ | 从工具输出到业务报告的实际加工过程，以及报告的用途。 |
| 6. 判断怎样产生 | 报告中哪条信息真正改变了你的决定？ | 为什么认为它重要？有什么其他解释？最近一次看到竞品变化却决定忽略，是什么情况？哪些信息最终没有进入报告？ | 判断依据、信号筛选与例外。 |
| 7. 怎样交给美工 | 如果这次涉及图片或卖点，你实际交给美工的材料是什么？ | 能展示一次交接吗？哪些由你决定，哪些由美工决定？对方问了什么？第一版回来后改了哪里、为什么改？ | 从分析结论到制作要求的转化与返工原因。 |
| 8. 时间与费用 | 回看这次，从查资料到可执行方案，各环节大约花了多久？ | 哪些是主动操作、哪些是等待？“一套图几百元”具体包含哪些交付和修改轮次？7 张图和 A+ 是否属于同一份报价？ | 总耗时、协作成本及费用范围。 |
| 9. 结果怎样判断 | 执行之后，你后来观察到了什么？ | 什么时候看、看哪些记录？同期还有哪些广告、价格、库存等变化？什么支持了原判断，什么还不能确定？ | 效果检查方法与证据限度。 |
| 10. 现有方式如何改 | 回看这次，哪些步骤你希望保留，哪些最想改变？ | 为什么？以前尝试过哪些办法，结果怎样？如果只能先改一处，你选哪里？ | 真实优先级、既有替代方案与采用障碍。 |

**追问方式：**遇到“通常”“一般”“AI 可以”时，回到这一次具体经历。遇到“分析”“判断”“优化”时，请她展开输入、依据和实际动作。先让她自己描述，再补问遗漏项，避免把访谈变成对现成 AI 方案的认可测试。

### 访谈之后：验证自有产品能否承接

先确认一项具体任务及“完成”的标准，再用同一份真实材料试做。暂未提供自有产品的能力清单，这里只列验证方式。

1. **请她使用：**“请按你刚才的工作要求，用这个结果继续完成任务。”观察她停在哪里、需要补查什么、修改什么。
2. **追问差异：**“与原来的做法相比，哪些步骤省了，哪些步骤增加了？哪个结果你还不能直接用？”
3. **问采用条件：**“如果下次再做同一项工作，你会选择哪种做法？还缺什么才会换？”若涉及团队采购，再确认谁决定、谁使用、预算如何判断。

| 试做结果 | 产品判断 |
| --- | --- |
| 已能完成任务，用户主要是不知道怎么用 | 改介绍方式、操作引导或示例。 |
| 能完成主要部分，但反复缺相同配置、模板或数据对接 | 评估配置与流程改进，并核对改完后还需多少人工。 |
| 确有能力缺口 | 比较需求频率、影响、其他用户是否相同、现有替代方案及实现成本，再决定是否新增。 |
| 使用后没有净收益，或超出产品服务范围 | 记录不做的理由，保留用户当前更合适的方案。 |

### 现场记录模板

| 项目 | 记录 |
| --- | --- |
| 案例与触发事件 | 产品、时间、为什么启动这次工作 |
| 原始证据 | 页面、工具导出、报告、交接材料的具体位置 |
| 实际步骤 | 用了什么工具，做了什么人工处理 |
| 时间口径 | 当前 / 过去；主动操作 / 等待；对应多少 SKU 与竞品 |
| 关键判断 | 当时考虑的解释、采用或排除的依据 |
| 采取的动作 | 改了什么，由谁执行，交付了什么 |
| 观察到的结果 | 数据或反馈；同期变化；仍不能确定的部分 |
| 研究者理解 | 对用户问题的解释，单独注明，避免与原话混写 |
| 待验证问题 | 需要补材料、再次观察或找其他运营核对的内容 |

## 二、竞品分析的阶段性用研总结

### 核心判断

**受访者已用工具减少部分查数和采集工作，仍需亲自把竞品信息与自家产品比较，形成市场报告，并用于图片和卖点优化。值得继续挖的是“拿到数据之后，怎样形成可以执行的判断”。** 当前每天约 2 小时的范围尚不清楚，还不能确定剩余工作中哪一步最值得优先解决。

### 已知事实：来自当前访谈转述

- 受访者把竞品分析、日报月报、关键词跟踪列为耗时占比最大的三项工作。竞品分析约每日人均 2 小时，尚未确认是工具使用前还是当前耗时，以及所包含的步骤。
- 竞品候选来自叶子类目 Top 100 榜单，再选与自家产品相似的对象进行每日跟踪。实际跟踪数量、自家 SKU 与竞品的对应关系尚未说明。
- 平时主要通过卖家精灵查数。八爪鱼已减少部分采集工作，采集结果仍需人工整合进自己的市场报告，并与自家产品比较。
- 重点关注排名、价格、促销活动及力度。截图还列出 Review、Listing、图片、卖点、新品、库存等信息，实际频率和重点需要逐项确认。
- 报告用于图片视觉优化和卖点提炼，图片由美工制作。受访者提到“7 张图”“A+ 约 7 个板块、每块 4–5 张图”和“一套图几百元”，这些属于她描述的制作范围与费用，尚未核实是否对应同一项交付。
- 截图右侧的“AI 分析原因、判断竞争影响、生成提醒”是待讨论的方案表达，本次材料尚未证明这些环节已经运行或产生效果。

### 对业务的初步理解

当前描述可以先拆成三个相连的任务。这个划分是研究者的理解，需要受访者核对。

| 任务 | 想完成的事情 | 需要进一步确认 |
| --- | --- | --- |
| 日常竞品跟踪 | 识别重点竞品发生了哪些值得关注的变化。 | 哪些内容每天看，哪些按周或事件触发？什么变化可以忽略？ |
| 专题对标与市场分析 | 把竞品信息与自家产品比较，形成有依据的判断。 | 专题由什么问题触发？报告给谁看？哪些结论会改变决策？ |
| 转为内容与运营动作 | 把发现转成图片、卖点或其他运营改动，并检查结果。 | 如何向美工说明改动？谁决定采纳？如何判断改动是否有效？ |

**初步用户任务表述：**当重点竞品出现变化，或自家产品需要优化时，运营希望用可核对的信息判断哪些差异值得处理，把判断转成清楚的执行要求，并能回看处理结果。

### 初步发现与待验证假设

| 发现 / 假设 | 当前依据 | 还不能下的结论 | 下一步怎样验证 |
| --- | --- | --- | --- |
| 采集后的整合可能仍占用较多时间。 | 已有查数和采集工具，但市场报告仍手工制作。 | 不能据此认定“报告整合”就是最大瓶颈，也不能承诺节省全部 2 小时。 | 观察一次报告制作，记录字段对齐、补数据、复制整理和分析各自耗时。 |
| 运营需要筛选“值得行动的变化”。 | 工作从记录竞品动态延伸到判断影响与制定对策。 | 不能把某项变化自动视为对自家销量或转化的原因。 | 对照一次采取行动与一次保持不动的案例，追问证据和判断规则。 |
| 分析与美工之间可能存在交接损耗。 | 竞品报告用于视觉优化与卖点提炼，美工负责制作。 | 当前没有证据证明返工严重，或制作费可以被 AI 节省。 | 对照原报告、设计要求、初稿和修改意见，找到信息丢失或理解不一致的位置。 |
| 日常监测与深度分析可能需要不同产出。 | 一方面每日跟踪，一方面形成市场报告和内容优化建议。 | 尚不清楚两者是否是同一工作、是否都计入 2 小时。 | 还原一周的任务日历，核对频率、触发点、接收人和交付物。 |

### 怎样从调研进入产品判断

**下一步先验证一段完整任务：已有数据 → 自家与竞品比较 → 一条有依据的结论 → 一项执行要求。** 用它检查自有产品到底覆盖了哪一步、人工补在哪里，再决定产品范围。

| 如果观察到的主要困难是…… | 优先验证的方向 |
| --- | --- |
| 重复复制、字段对齐、格式整理 | 数据接入、匹配规则和报告模板；先核对现有工具能做到多少。 |
| 阅读大量 Listing、评论、图片并提炼差异 | 试验 AI 提取和对比；保留原始来源，让运营检查遗漏和错误。 |
| 变化很多，但不知道哪些值得处理 | 还原运营的筛选依据和例外，再试验规则或 AI 辅助筛选。 |
| 判断难以转成清楚的美工要求 | 试做带证据的修改说明，检查美工能否理解、追问和返工是否减少。 |

报告自动生成后，还要观察它是否帮助用户作出决定。竞品变化的原因、对自家经营的影响，需要额外证据；AI 可以提供待核查的解释，不能仅凭两项数据同时变化就当成已确认原因。

产品中的直接用户首先是运营；美工和报告接收人可能是协作用户，需进一步确认。竞品评论和消费者反馈能帮助理解消费者需求，但设计这个运营工具还需要研究运营本人如何工作。

### 后续评价方式

- **效率：**同等工作量下，从拿到资料到形成可执行方案的总人工时间，包含核对、修改和交接。
- **质量：**数据与来源对应是否准确，重要变化是否遗漏，结论需要多少人工纠正，设计要求是否清楚。
- **业务结果：**记录改动后 CTR、CVR 等表现；结合样本、同期变化和实验条件判断证据，避免仅凭前后变化认定因果。

**下次最值得补的一组材料：**同一次工作的原始采集结果、最终市场报告、对应自家产品页面、给美工的要求及修改记录。用这组材料核对她讲述的流程，再决定教学主案例和产品范围。
