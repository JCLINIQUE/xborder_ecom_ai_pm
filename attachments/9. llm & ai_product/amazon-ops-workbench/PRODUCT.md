# 亚马逊精品运营工作台 · MVP 范围

## 只保留四个侧栏入口

| 页面     | 用户要完成的事                                    |
| -------- | ------------------------------------------------- |
| 数据导入 | 上传、粘贴或 MCP 读取资料，核对结果，恢复上次资料 |
| 数据报告 | 查看真实数据，筛选、添加和编辑可视化              |
| AI 分析  | 修改分析要求，调用模型，编辑和下载结论            |
| 日报导出 | 生成草稿，修改正文，下载报告                      |

“工作空间”原先只是保存一批文件、图表、分析和日报的技术容器，不应成为用户必须理解的产品概念。“运营节奏”“运营行动清单”“智能运营”等分组已从主界面移除。

保留 Day 05 的暖色界面与可点击侧栏，不照搬其业务模块。不自动加载任何模拟数据。不把待办、店铺授权或自动执行运营动作塞进第一版。

## 设置归属

- **模型连接**是右上角的独立对话框：服务商、模型名、API Key，在本次页面会话共用，与资料切换无关。刷新后需重填，服务端只转发请求，不持久化 Key。
- **分析 Prompt**在 AI 分析页修改，随本次资料保存。
- **日报 Prompt**在日报页修改，随本次资料保存。
- **MCP 连接**放在数据导入页的弹窗，独立于模型连接。授权链接仅在弹窗内存中保留，关闭即清空；不随资料保存。
- 用户修改后的分析结论可以带入日报；下载使用当前编辑内容，不只导出最初的 AI 回复。

## 数据边界

支持 Excel / CSV、截图 OCR、TXT、Word DOCX、PDF。截图、扫描 PDF 及文档以可核对的文字证据为主，不承诺任意版式都能自动变成正确表格。旧版 DOC 先转换成 DOCX。具体容量限制见 README。

所有资料先人工确认，再参与计算和分析。缺失值不当作零；不自动把不同统计口径的表格相加。用户可自定义图表、第二指标、目标线和说明，但没有数据时不生成虚假趋势。

模型输入包含当前表格指标、最多 100 行筛选明细，以及每份已确认文字最多 12,000 字符。会向模型说明截断和缺失信息。编辑结果仍需人工核对，模型不直接修改店铺。

## 可复用代码

- `lib/ops/domain.ts`：资料、表格、图表、分析和日报的数据契约，指标计算与证据摘要。
- `lib/ops/importers.ts`：各类文件解析与 OCR，不依赖页面布局。
- `lib/ops/mcp-import.ts`：把 MCP 响应转为同一种资料结构，保留来源与原始响应；不依赖交互模式。
- `lib/ops/mcp.ts`、`app/api/mcp/route.ts`：已审核查询清单、实时参数、MCP 连接、额度确认与只读边界。
- `lib/ops/workspace-context.tsx`：共享状态、保存恢复、分析动作。内部保留 Workspace 类型名，仅代表一份资料记录，UI 不暴露该概念。
- `app/api/`：资料持久化、原文件读取、模型代理。
- `components/workbench/`：当前四步式工作台界面。

以后切换为对话、画布或其他交互时，优先复用以上数据和服务；本版不添加未实现的模式切换。任务委派式 Agent 还需要任务状态、确认、重试等能力，不能仅靠换前端宣称实现。

MCP 第一版接入西柚洞察（用户在 Codex 中命名为 xyzc-mcp）。流程是连接授权、选择查询、读取预览、人工导入、字段核对；不会让 AI 自动选工具或扩大读取范围。授权链接由用户在独立工作台输入，不从 Codex 自动复制凭证。只开放 8 种常用查询，其余工具暂不提供。

该来源提供第三方商品、关键词和流量资料，不代表接通了卖家店铺；没有实现 Amazon SP-API / Ads OAuth。MCP 结果复用所有下游功能，仍不自动填充模拟数据。
