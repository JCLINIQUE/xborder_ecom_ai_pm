## 1. 从 Day 03 到本版：可信数据 → 变化解读 → 运营判断

[Day 03 示范](<../3. prd/Day03产品功能设计.md>)从一次价格／促销事件推导出 F1–F4。本稿把数据核验与变化对比做成工作台，并接回 F3 的辅助判断；首版围绕价格／促销说明值得关注什么、还要核实什么，由运营取舍。

| Day 03 的功能 | 本版怎样承接 |
| --- | --- |
| F1 关联并核验跟踪记录 | 细化为资料导入、信息提取、字段映射与人工核对。 |
| F2 识别价格／促销变化 | 细化为按商品和时点积累记录，展示前后差异及横向对照。 |
| F3 辅助排查与处理判断 | 由 W6 承接：调用大模型，基于已核对数据与程序计算结果，输出变化解读、核查项和有条件的处理方向。 |
| F4 记录运营决定 | 后置。允许写数据核对备注，不要求填写“跟进／观察／忽略”才能使用表格。 |

## 2. 用户、问题与目标

**用户与场景：**负责已有商品日常经营的电商运营，持续跟踪自己选定的竞品。首版以亚马逊为字段样本；运营定期把已有工具导出的表格、商品页面截图、整理过的 Word 资料放进同一工作台。

[调研示例](<../1. user-research/用户调研报告-亚马逊精品运营-20260914.md>)已提供“工具漏抓后人工核验、用 Excel 比较前后记录”的线索。本次明确的产品方向是把多种资料整理到表格中；三类文件的真实占比、复杂程度和整理成本仍需样本验证，不能据此承诺节省多少时间。

**核心需求：**运营希望减少重复抄数和来回找资料，在一张表里看清“哪个商品、什么时间、什么数值、来自哪里、能否比较”，进一步理解变化可能意味着什么、还缺哪些证据，再自行判断业务动作。

**目标产出：**可持续补入新记录的跟踪表、对照视图，以及按需生成的价格／促销解读；可导出数据和用户选择附带的解读。服务日常竞品追踪，不承担选品、市场规模分析或新品定位。辅助判断的实际价值仍需真实案例验证。

## 3. 首版范围

| 本版包含 | 本版边界 |
| --- | --- |
| 多个已选自家／竞品商品，按站点、ASIN／变体、卖家关联。 | 用户确认跟踪对象，不自动发现竞品。课堂先用一款自家＋一款竞品＋两个时点验证。 |
| 上传 PNG/JPG 截图、`.xlsx`、`.docx`，可一次选多份。 | 旧版 `.xls`／`.doc` 提示先转换；不支持的、加密的或损坏的文件单独提示原因，其他文件继续。 |
| 提取标价、优惠展示及条件、评分、评论数、BSR 及类目等固定字段。 | 关键词排名、流量与销量估计、评论内容分析、图片卖点分析暂不纳入标准比较；原资料保留供查看。 |
| 校对入表、历史记录、筛选排序、前后及横向比较、导出。 | 不自动调价、投放或发布；不增加协作审批、定时预警。 |
| 调用大模型解读价格／促销变化，给出关注理由、待核实项和有条件的处理方向。 | 首版不生成改图、流量、差评等事件的分析；不把推测写成确定原因，不替运营拍板。 |

**不做爬虫：**不登录平台、不访问商品链接抓数、不定时拉取或自动刷新外部数据。资料中的 URL 只保存为来源地址；表格内外链、Word 外部链接也不作为取数入口。用户需自行补充新资料。

## 4. 用户流程与功能

**建立跟踪清单 → 上传资料 → 提取并核对入表 → 对比变化 → 按需辅助分析 → 运营判断 → 保存／导出或继续补证。** 查看与导出表格不以调用大模型为前提。

| 功能 | 用户与系统怎样完成 | 输出 |
| --- | --- | --- |
| **W1 导入并归属资料** | 用户选择已有商品或新建商品，上传文件；一份文件包含多个商品时可逐行关联。系统记录上传时间，另行提取或请用户补“资料反映的观察时间”。不按商品名猜测合并。 | 原文件、处理状态、候选商品与时点；缺身份的资料留在待整理区。 |
| **W2 提取并映射字段** | Excel 读取选定工作表的单元格；Word 读取段落与表格；截图及文档内图片用 OCR／图像识读。将原列名和文本映射到固定字段，展示原文、候选值和来源位置。用户可改映射。 | 候选记录及未识别项，尚不作为已确认数据。 |
| **W3 人工核对并入表** | 用户在原资料与候选表之间核对商品、时间、字段含义和数值，修正误识别，处理重复和冲突。支持确认所选记录；缺失项仍保留缺失状态，不强迫补造数值。 | 已核对的可用字段、待补字段和修订记录。 |
| **W4 跟踪与对比看数** | 查看商品历史，筛选站点／商品／观察时段／状态，选择字段排序。可选择同商品两个时点看变化，或选同一观察日的多个商品横向看数；不具可比性的字段说明原因。 | 原始值、差值、口径与状态并列的表格，可点任一值回查来源。 |
| **W5 保存与导出** | 保存跟踪清单、原文件、提取记录及人工修订；W6 的解读另存为带数据版本的草稿。按当前筛选导出 `.xlsx`，包含对照表、所用记录和来源／待核对说明，可选附带已复核的当前解读。 | 可继续使用的工作台与含来源说明的导出文件。无需先生成解读或填写经营决定。 |
| **W6 变化解读与核查建议** | 用户选商品、时段或一条价格／促销变化，点击“辅助分析”；可补充相关自家经营数据、目标与约束。系统将核对后的数据、规则计算和证据缺口交给大模型，生成可回查、可编辑的解读。 | “发现了什么、为什么值得关注、还需核实什么、可以考虑什么方向”四部分草稿。运营复核并决定是否行动。 |

处理进度按文件展示“等待、处理中、待核对、完成、失败”。单文件失败可重试或改为手工补录，不丢失其他成果；重新提取先预览差异，不覆盖人工修订。

### W6 怎么调用大模型，谁负责哪一步

**程序负责算数和判断可比性，大模型负责解释与组织核查思路，运营负责事实复核和经营取舍。** W6 的结果不会回写成已确认的原始数据，也不会触发经营动作。

**输入：**用户选定范围内已核对的字段与来源编号、观察时间和口径，W4 算出的差值与条件计算，缺失／冲突的状态，以及用户主动补充的相关自家经营信息、目标和约束。补充信息标明来源、适用时段与“用户提供”；普通备注不自动作为已核实事实。未核对数值不作为分析依据，不自动访问链接补数。

| 输出部分 | 应写清什么 |
| --- | --- |
| 发现了什么 | 复述有证据的数值与变化，引用对应记录；计算结果沿用程序输出。 |
| 为什么值得关注 | 写可能影响和成立条件；明确区分观察事实、条件计算与待验证解释。 |
| 还需核实什么 | 按本次判断需要列优先核查项，说明缺什么以及影响哪一步判断。 |
| 可以考虑什么方向 | 给出有条件的处理方向，如先核券条件、补自家数据、观察或评估促销；不输出无依据的确定行动指令。 |

使用规则：

- **证据不够时缩小结论。** 缺旧记录时只解读本次观察，说明无法确认变化；缺自家经营背景时给核查方向，不推断销量归因或直接要求跟价。没有可用的已核对事实时提示先核对资料，不生成事件判断。
- **结果先作为草稿。** 程序检查来源编号和引用数值是否存在、是否与输入及计算一致；检查失败的结果标为不可用，可重试。运营查看来源，复核陈述是否受到证据支持，编辑或删除后确认；“已复核”不把可能解释变成事实。
- **允许跳过与失败恢复。** 分析中、失败、未复核、已复核、依据已变化分别提示。失败或超时可重试，表格照常查看、补数与导出，不用模拟文案冒充模型结果。
- **绑定分析时的数据。** 记录分析范围、输入版本及生成时间。相关数据、条件或自家背景被改动后，原解读立即标“依据已变化”，撤销复核状态；生成期间发生改动，返回结果也标为已变化。保留旧解读及人工修改，新结果作为候选供复核，不静默覆盖。

## 5. 表里存什么，哪些值可以比较

**一条观察记录表示：某站点、某商品／变体、某卖家，在一个明确时点的资料快照。** 不同日期的记录持续追加，不用今日数值覆盖昨日。每个字段分别保留来源、原文、提取值、人工修订值与状态。

| 字段组 | 首版字段与要求 |
| --- | --- |
| 身份 | 自家／竞品、商品简称、站点、ASIN／变体、卖家。简称便于找商品，不能代替身份。 |
| 时间与出处 | 观察日期／时间及其精度、时区（涉及具体时间时）、上传时间、文件与位置。来源定位到截图区域、Excel 工作表与单元格、Word 段落／表格单元格或内嵌图片。 |
| 价格与优惠 | 币种、当前售卖标价（未扣券）、券面额或折扣、适用条件、优惠展示情况，分别存储。划线／参考价保留为另种价格类型，不混入标价列；类型不明时待核对，不计算价差。未知资格或期限须显示未知。 |
| 其他看数指标 | 评分及量表、评论数、BSR 数值与榜单类目。BSR 与关键词排名分开，不混作同一种排名。 |
| 核对状态 | 待核对、已核对、冲突待处理；缺值另标“未提供／识别失败／页面未展示”等原因。“已核对”表示与材料核对，不表示验证了平台实时真值。 |
| 修订与备注 | 原提取值、修订后值、修改时间、修订说明；备注用于解释数据，不自动转成事实字段。 |

### 核心业务规则

1. **缺失不是零。** 看不清的价格留空并标识；优惠字段未采到不等于没有券，“页面未展示”也不等于所有买家没有优惠。禁止用猜测补值。
2. **观察时间不是上传时间。** 不取上传时间、文件修改时间冒充观察时间。缺时间可保存，补齐前不进入时间变化计算；只有日期时按日展示，不编造具体时刻。同日多份资料时间顺序不清时并列待选。
3. **格式转换保留原意。** 币种、单位、千位符和百分比含义需明确；歧义值待核对。Excel 公式仅读取已有计算结果并标明来源；无可用结果时请用户补充，不执行宏或刷新外部引用。合并单元格、复杂布局造成映射不确定时先预览确认。
4. **重复与冲突分开处理。** 完全相同文件重复上传提示复用，不重复新增记录。同商品不同日期即使数值相同，也保留新观察。同身份、时点、字段与口径的同值可合并来源；不同值并列为冲突，由用户核实或更正时点，不能后上传覆盖先上传。
5. **比较按字段判断。** 只有已核对、身份／时间／单位／口径满足要求的值才计算差异。某一字段缺失不阻止其他字段比较。待核对值可显示，明确排除于确定差值和排序；缺值放末尾，不能按零排序。
6. **纵向与横向各有条件。** 纵向比较同站点、同 ASIN／变体、同卖家的两个时点；横向由运营选商品、确认规格可比，并显示各自实际观察时间。价格不跨币种直接相减，也不擅自换算；不同日的值不伪装成同日快照。BSR 只在同站点同类目下计算差异，排名变小只说明排名数字变化，不推断销量。
7. **券与标价分列。** 券条件不明时，表中仍可比较标价，券单独列为待核实。可显示“若券适用，标价减券为 X”的条件计算，但不能代替标价列、作为确定成交价参与排序，或称为真实降价。
8. **修订影响结果。** 修改已入表值后，受影响字段重新核对，相关差值暂标待更新；确认后重算，保留旧值与修订记录。删除被引用的来源前提示影响，撤去唯一依据则相应字段失去确认、停止计算；历史导出文件不自动更新。
9. **导出保持状态。** 导出前预览范围与待核对项，表内保留值、单位、时间、缺失与确认状态、计算条件。无有效对照时仍可导出资料整理表，并注明未形成有效对照。可选附带与本次导出范围一致、依据未变且已复核的解读，单独成页保留四部分、引用、条件及生成时间；未满足时只导出数据并提示原因。来源附文件名、定位信息及工作台内记录编号；不把他人无法打开的本地路径当作可用溯源链接。原文件继续在工作台回查，外发需用户另行提供原材料。

## 6. 同一案例怎样进入工作台

继续使用 Day 03 的 A-1、A-1-I、A-2、S-1/2。**以下文件分配只是演示三类输入怎样汇合的教学设计，并非已经取得这些格式的真实附件；数值均为模拟。**

| 示例输入 | 提取与核对结果 |
| --- | --- |
| Excel：A-1、S-1/2 | A-1 为 9 月 10 日 10:00，竞品标价 11,800 日元，券字段未采集；自家两日标价均为 10,800。 |
| 截图：A-1-I | 经确认与 A-1 为同商品、同卖家、同时点的页面，未展示券。补充到原观察的来源中，不另造一个时点。 |
| Word：A-2 的记录或内嵌截图 | 9 月 11 日 10:00，竞品标价 11,800，展示 2,000 日元券，资格与期限未知。时区由用户补充确认。 |

核对后，前后对照显示：

| 对象／字段 | 9 月 10 日 | 9 月 11 日 | 表格中的结果 |
| --- | --- | --- | --- |
| 竞品标价 | 11,800 日元 | 11,800 日元 | 标价差 0。 |
| 竞品优惠展示 | 页面未展示券 | 展示 2,000 日元券，条件未知 | 两次优惠展示不同；不写“确定降价 2,000”。 |
| 自家标价 | 10,800 日元 | 10,800 日元 | 标价差 0。 |

若用户确认两款规格适合横向比较，同日标价对照为“竞品比自家高 1,000 日元”。另列条件说明：“若券适用，11,800 − 2,000 = 9,800，比自家标价低 1,000”；该条件值不参与确定成交价比较。

点击“辅助分析”后，W6 应组织成以下草稿。**这是预期输出示例，不是实际模型运行结果。**

| 输出部分 | 本例预期内容 |
| --- | --- |
| 发现了什么 | 竞品两期标价均为 11,800 日元〔A-1、A-2〕；旧页面未展示券，本次展示 2,000 日元券、条件未知〔A-1-I、A-2〕；自家标价为 10,800〔S-1/2〕。 |
| 为什么值得关注 | 若券适用，程序计算的 9,800 比自家标价低 1,000，可能改变可享优惠买家的价格比较；这个判断依赖券资格和商品可比性〔A-2、S-1/2〕，不能据此认定竞品在清库存或抢走自家销量。 |
| 还需核实什么 | 先补券资格、期限〔A-2 的缺项〕，再补自家同期销量、转化、广告及利润约束〔S-1/2 未提供〕，判断是否需要进一步处理。 |
| 可以考虑什么方向 | 可先核实优惠条件；信息暂时拿不到时继续观察。若优惠确实适用，且自家经营数据与利润约束支持，再评估促销方案。当前不足以直接给出跟价结论。 |

运营可以编辑解读、补充证据或暂不行动；首版不要求另填决定表，也不会自动执行价格、广告或促销动作。

撤去 A-1-I 后，旧优惠状态回到“未采集”，不能继续确认两次优惠展示变化；标价两期不变的对照仍可用。旧解读标“依据已变化”，新解读应说明“本次展示了券，尚无法确认是否新增”，优先核查旧记录。这样能同时检查表格与模型解读是否随证据变化。

## 7. 业务验收

## 8. Day 04 怎么用与后续补充

**课堂：**先用第 1 节说明首版取舍，再沿同一条记录走“文件 → 核对成表 → 程序比较 → 模型解读 → 人工取舍”。例如删掉观察时间或旧截图，讨论哪一格还能比较、哪一句解读应撤回、下一步需要补什么。

**当天产出：**修订后的这份业务版 PRD，并用配套原型走查正常完成、部分失败、修改后三条路径，将发现的规则缺口回写本稿。原型沿用“资料准备 → 分析工作台”两页结构，包含资料核对、跟踪表、辅助分析和来源详情；目录内旧 SSD 原型不作为本稿的配套方案。

进入原型与实现前，补齐三类真实样本及价格／促销判断案例，确认常见表头、复杂文档与语言、每批文件数／大小／行数、处理时长和保存方式。技术课再确定 OCR、文档解析、辅助判断模型选型与输入组织、数据架构及质量评测。资料存储位置、保留期限及识别／模型服务需在使用真实业务材料前明确。

价值验证先比较“现有工具＋手工整理”与工作台的整理加核对总耗时、字段错误／漏项、返工和来源查找成本；再在同一份已核对数据上比较“只看表”与“表格＋辅助解读”，检查引用、条件遗漏、无依据归因、解读修改成本及核查建议是否有用。先取得基线，再定目标，不预填准确率或提效承诺。
