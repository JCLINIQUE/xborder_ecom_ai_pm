# Day 04｜用 Figma 或 XMind 把业务规则变成原型

> 历史 SSD 原型参考。当前 Day 04 使用 [竞品追踪工作台业务版 PRD](<业务版PRD-竞品追踪工作台.md>)；本文的页面、编号与验收不直接适用于新方案。

**今天完成：一份可以逐步走查的原型。** 用户看到什么、点击后发生什么、不能继续时怎样恢复，都应在原型中找到答案。本文保留旧版 SSD 原型教学示例，使用原示例编号与模拟资料，待与当前 Day 03 的业务版 PRD 衔接。

配套：[页面与交互说明](<页面与交互说明-竞品对比助手.md>) · [XMind 导入大纲](<竞品对比助手-XMind导入大纲.md>) · 线框参考：[P1 资料录入](<wireframes/P1-资料录入.svg>) / [P2 对比与复核](<wireframes/P2-对比与复核.svg>) / [P3 整理与导出](<wireframes/P3-整理与导出.svg>)

## 1. 选一个主要工具，交付同一套产品逻辑

| 工具 | 本课怎样使用 | 交付内容 |
| --- | --- | --- |
| **Figma** | 把页面画成 Frame（画框），复制关键状态，通过按钮连接页面或浮层。 | 3 个主页面、关键状态与可点击路径；标出对应 PRD 编号。 |
| **XMind** | 按“页面 → 信息与动作 → 条件 → 反馈与去向”组织结构，用页面编号连接往返关系。 | 有主路径和异常分支的结构原型；附 3 个页面的区域说明或线框。 |

可以任选一种作为主要作业。用 XMind 时，应让读者沿节点看懂一次任务怎样完成；用 Figma 时，应让每个可点按钮都有明确行为。两种方式都用同一组验收走查。

## 2. 把 PRD 翻译成用户看得见的东西

先确定桌面端单次任务的三页结构：**P1 资料录入 → P2 对比与复核 → P3 整理与导出**。返回修改也是主流程的一部分。

| PRD 要求 | 原型中画什么 | 为什么这样安排 |
| --- | --- | --- |
| R1：缺项允许保存，格式错误需纠正。 | 商品列表保留 C1；编辑区标出接口、形态、价格口径缺失。金额非法时，错误放在金额字段旁。 | 用户能知道具体补哪里；一条记录不完整不会遮住其他可用资料。 |
| R2：价格与图片分别判断。 | P2 分成价格比较、图片表达两个区域。B1 价格行标容量不同，图片区域仍列参考。 | 用户能够按不同目的使用同一商品，不会误把“价格不可比”理解成整件商品都不能用。 |
| R3：结论可回查、可修改。 | 来源按钮打开材料名称、位置与可选链接；结论旁显示依据和编辑入口。 | 帮助用户核查这句话，而不是只看到一串来源编号。 |
| R3：复核后才能导出。 | P3 放保留内容预览、下一步决定与理由、整体确认，再显示导出按钮及禁用原因。 | 让确认发生在用户看过实际导出内容之后。 |
| R4：生成可失败，草稿需复核。 | 选用 AI 时补生成中、失败和无效引用状态；保留手动编辑入口。 | 用户遇到失败仍能继续原来的任务。 |

### 用 C1 示范一次具体设计

PRD 写“缺项不计算价差”。原型要继续回答：

1. **提示出现在哪里：**P1 的 C1 行显示“待补信息”；打开编辑区，逐项列出缺失字段。
2. **还可以做什么：**已有 S1 和竞品记录时，可进入 P2；C1 不算价差，A1 仍显示比自家标价低 820 日元。
3. **怎样恢复：**点击 C1 的“补充资料”，返回 P1 并定位该商品；补齐并保存后重新判断。
4. **影响哪些旧结果：**修改资料后旧草稿清除、确认取消。用户看到“资料已更新，请重新复核”，而不是带着旧确认继续导出。

在 Figma 中为这条分支连线；在 XMind 中把条件和去向写进节点。仅在页面角落写“支持异常处理”，不能完成这段说明。

## 3. Figma 路线：先画主页面，再连接状态

**第一步：建立画框。** 在同一个设计 Page 中建立 P1、P2、P3 三个顶层 Frame，宽度保持一致。可以参照配套 SVG 重画，或将 SVG 导入画布作底稿，再检查中文、分组和布局。导入 SVG 得到矢量图层，页面跳转还需要自己设置。[Figma 素材导入说明](https://help.figma.com/hc/en-us/articles/360040028034-Add-images-and-videos-to-designs)

**第二步：用具体内容排版。** 先放自家 S1、竞品 A1/B1/C1 和缺项提示，再放按钮。价格区要展示“口径、金额、价差、状态、原因、来源”，图片区展示人工观察及其来源；不能只用几个空白矩形代表关键判断。

**第三步：复制关键状态。** 用 P1-empty、P2-mixed、P2-updated、P2-none、P3-unconfirmed、P3-confirmed 等名字区分同一页面的状态。先做“载入样本 → 比较 → 填决定并确认 → 导出结果预览”，再补“修改资料后确认失效”和“无有效对照不能导出”。

**第四步：连接并预览。** 选中按钮，在 Prototype 中设置点击触发，连接到目标 Frame；来源详情可用浮层，完成后返回原页面。把 P1 设置为起点，从起点预览完整任务。[Figma 原型操作说明](https://help.figma.com/hc/en-us/articles/360040314193-Guide-to-prototyping-in-Figma)

课堂可通过跳到预设状态展示“价格从 8,980 改成 10,000”，不用先实现任意输入和计算。明显标注“交互演示／教学模拟”；导出按钮可连接到导出内容预览，这不代表已经实现下载。真实计算和文件导出由 Day 05 的 Demo 验证。

## 4. XMind 路线：把功能目录改成可以走的路径

在 XMind 中通过 **File → Import → Markdown** 导入配套大纲；标题与缩进列表会转换为主题层级。导入后检查首个中心主题、页面层级及分支是否完整。[XMind 官方导入说明](https://xmind.com/user-guide/markdown-to-mind-map)

一级主题使用 P1、P2、P3；每页继续列“页面信息”和“操作分支”。例如：

> P3 → 导出 → 是否保留有效对照？ → 是 → 决定与理由是否填写？ → 是 → 是否已确认本次内容？ → 是 → 导出预览；任一条件不满足，回到对应的补充动作。

“返回 P1 补 C1”要写出页面编号和定位对象；同时注明已填内容保留。仅有“录入、对比、导出”三个功能节点时，继续补上按钮条件、错误反馈与恢复路径。

在每页附上信息区域的顺序或配套线框，让接手者知道内容怎样组织。导入 Markdown 会得到结构层级，页面往返关系需按大纲中的编号补充，不能把树形排列当成自动完成的交互连线。

## 5. 用验收走查原型，并回补 PRD

走查时老师扮演用户，只按原型展示的提示前进；学员先不解释。卡住后记录：**对应 T 编号 → 看到了什么 → 不知道怎么继续 → 应修改哪个页面或哪条 PRD 规则**。

重点观察三个问题：C1 缺项时是否还能完成 A1 的比较；B1 的两种用途是否清楚；内容修改后能否看出原确认已失效。其余分支按配套交互说明覆盖 T1–T9；未选用 R4 时注明 T8 不涉及。

原型走查证明路径和规则表达清楚；试用是否省工，仍要在真实任务中核对。若画图时发现“用户排除的是价格还是图片”说不清，应先明确作用范围，再同步到 PRD，避免留给制作 Demo 时猜。

## 6. 60 分钟课堂与课后作业

| 时间 | 具体安排 | 产出 |
| --- | --- | --- |
| 课堂 15 分钟 | 老师将 C1 缺项规则翻译为提示、按钮、去向与恢复，用选定工具示范。 | 一条完整的原型分支。 |
| 课堂 30 分钟 | 学员完成 P1–P3 正常路径，补“修改后重新复核”和“导出前确认”两个状态。 | 第一版可走查原型。 |
| 课堂 15 分钟 | 老师按 T2、T4、T5、T6 走查；学员记录并修订。 | 问题记录与修订决定。 |
| 课后 60 分钟 | 20 分钟补其他异常状态；25 分钟按 T1–T9 走查；15 分钟同步 PRD 与交付记录。 | 完整原型、走查记录、必要的 PRD 修订。 |

**交付：**Figma 文件／原型入口，或 XMind 文件＋页面布局说明；页面与状态有编号；记录每条适用验收的路径、发现与修订，未覆盖项明确列出。配套 SVG 是静态线框底稿，XMind Markdown 是导入材料，课堂作业还需在选定工具中完成连接和走查。

Day 05 按同一份 PRD 和原型制作 Demo，实际实现录入、规则计算、复核和导出；交接时指出哪些原型效果只是预设演示。
