# Day 02｜产品需求提炼：从真实工作中找到值得改善的问题

**本课目标：**从调研与真实报告中提出 2–3 条候选需求，说明依据和证据缺口，再推荐一条继续深入。

材料：[用户调研报告](<../1. user-research/用户调研报告-亚马逊精品运营-20260914.md>) · [桌麦市场调研](<../5. demo/桌麦市场调研.xlsx>) · [课堂练习与参考答案](<Day02课堂练习与参考答案.md>) · [需求清单模板](<产品需求清单模板.md>)

## 1. 今天研究哪一段工作

本课以真实《桌麦市场调研》为案例，研究运营怎样将产品和竞品资料转成比较、定位及行动建议。原访谈展示的是 SSD，桌麦报告用于补充工作方法和实际产出，两类商品的数据与结论分别使用。

先还原工作：**取得资料 → 选择比较对象 → 整合与比较 → 形成判断 → 支持后续行动。**

| 已有证据 | 支持我们继续调查什么 | 尚不能认定什么 |
| --- | --- | --- |
| 访谈提到工具采集后仍有补录、核验和多份资料整合。 | 工具之后还剩哪些操作，分别造成什么困难。 | 所有人工步骤都低效，或采集仍是最大的瓶颈。 |
| 桌麦报告已有产品特征、竞品对比、定位和图片方向。 | 一条业务判断用了什么资料、怎样形成、后来如何使用。 | 这些判断均已核实，或建议已经执行并改善销量。 |
| 《评论分析》A5:C9、E5:G9 复用了表内工具截图中的分析汇总。 | 工具已经完成什么，运营又补充了什么判断。 | 整份报告都是人工从零分析，新产品能省下全部时间。 |

这次已经取得真实报告。下一步应回溯具体操作与使用情况，确认报告涉及的自家商品和版本；报告中的商品属性也要与自家资料核对后才能采用。

## 2. 老师示范：追踪一条结论怎样形成

先看基础材料，再对照作者结论。课堂中可先遮住《调研结论》，让学员提出自己的解释；原报告是实际产出参考，不是唯一正确答案。

| 阅读位置 | 报告里有什么 | 课堂要追问什么 |
| --- | --- | --- |
| 《产品特征提取》C19:C28 | 记录了折叠、收纳、远程办公等特征与场景。 | 分别对应什么商品？来自参数、页面表述还是作者归纳？ |
| 《评论分析》A5:C9、E5:G9 及对应截图 | 已有场景、人群等分析汇总。 | 工具基于哪些样本分析？运营能直接复用什么，哪些还要核对？ |
| 《直接竞品对比分析（日本版）》C10、C15 | 出现便携、视频会议和桌面整洁等定位判断。 | 哪些资料支持这些判断？竞品是否也有相同特点？ |
| 《调研结论》A1 | 对 Uni S 提出“图需要体现便携性”。 | 为什么选择便携？这是必须表达的特点，还是有证据支持的差异优势？ |

可以沿 **产品特征与使用场景 → 便携定位 → 图片表达方向** 回溯作者思路。材料展示了这条路径，但每一步的判断理由和真实工作顺序仍需请作者说明。

### 把证据、判断和行动分开

| 层次 | 本案例如何表述 |
| --- | --- |
| **资料记录** | 报告记录了折叠、收纳等内容。能确认“报告这样写”，不等于已核实自家产品具备全部属性。 |
| **工具已有分析** | 评论页使用了现成的场景、人群汇总。需确认样本与适用商品，不能全部计为人工新增工作。 |
| **作者判断** | 报告将便携、会议场景用于定位，并建议在图片中强调。 |
| **行动建议** | 图片需要表达便携性。是否写成正式图需、交给谁、是否执行，尚待确认。 |
| **证据缺口** | 为什么优先选便携、与竞品有何差异、实际制作和使用情况，都需要补充。 |

**“图需要体现便携性”是运营的业务动作，还不是我们要开发的产品需求。** 要继续问：形成这条建议时，哪一步难以完成？用户需要什么帮助？

另一个可选练习入口是《痛点分析》A10、A23：作者将兼容说明、使用教程等归入运营方向，将质量、支架及配件等归入后端方向。它说明分析可能服务不同接收者，不能把所有问题都归给改图。

## 3. 从工作步骤提炼候选需求

“仍需人工”只是继续调查的线索。值得改善的问题需要查清：**现在仍发生、造成具体代价、现有办法没有充分解决。** 代价可以是耗时、漏项、返工或判断困难；等待美工排期与运营主动操作应分开看。

以下是课堂推导示例，候选需求及其价值仍待验证。学员可以提出不同选择，但要说明依据。

| 候选需求 | 已有依据 | 关键追问 |
| --- | --- | --- |
| **资料整理：**运营需要把多份资料对应到正确商品，减少后续比较时的重复整理。 | 调研提到跨报告整合，桌麦样本包含表格、链接和截图。 | 具体反复整理哪些内容？现有工具或统一模板能否解决？ |
| **辅助竞品分析与卖点选择：**运营需要结合自家和已选竞品资料，形成有依据的比较，选择适合自家的主打卖点。 | 样本从特征与场景推进到定位和图片建议，已有工具汇总仍需进入业务判断。 | 哪些比较、取舍最难？什么结果能直接采用，什么必须由运营补充判断？ |
| **图需交接：**运营需要把已确认的卖点转成美工能够执行的图片要求。 | 报告已有图片方向，补充访谈涉及美工协作；正式需求单尚未取得。 | 接收者会补问什么、为何返工？主要问题是要求不清，还是排期等待？ |

这三项位于同一工作过程的不同环节。不能仅凭最后出现“图片建议”，就认定图需生成最值得做；也不能因为输入包含表格、文字和图片，就把读取文件当成用户的最终目标。

## 4. 需求与方案分别写

以第二个候选为例：

| 层次 | 示例 |
| --- | --- |
| **用户目标** | 为自家商品选择值得重点表达的卖点，并说清理由。 |
| **问题假设** | 资料分散，工具已有分析与自家情况还要经过整合、比较和取舍；具体困难与代价待回溯。 |
| **候选需求** | 运营需要结合自家与所选竞品资料，形成可核查的比较和卖点候选，以便作出选择。 |
| **可能方案** | 规范对比模板、调整现有工具输出，或用 AI 辅助整理与分析。方案可以组合，也可以更换。 |

如果统一模板已经解决主要困难，就优先复用。如果 AI 草稿需要大量查错，生成速度快也不能证明价值。比较方案时固定任务和成果要求，计算 **准备、整理、核查、修改及交接的总人工时间**，并检查结果能否用于原工作。

访谈中的过去手动记录每天约 1–2 小时，属于工具使用前的回忆，不能当作当前市场报告的耗时，更不能直接写成 AI 的节省承诺。

## 5. 推荐一项继续深入，并说明为什么

**本课程示范选择“辅助竞品分析与卖点选择”继续进入 Day 3。** 它能承接报告中从资料到判断的实际路径，既研究已有文字和图片怎样被使用，也研究运营怎样比较和取舍。

下一天将围绕 **一款自家商品与少量人工选定的竞品资料 → 比较 → 有依据的卖点候选 → 运营确认** 设计功能。Day 2 先说明选择依据，不提前规定输入页面、按钮或技术实现。

这是一项适合继续定义和验证的课堂方向，不代表已证明收益最高。继续回溯时：

- 若主要代价在重复整理，且模板能够解决，应收缩到整理办法。
- 若运营需要的判断超出现有资料，先补资料与判断依据，不能靠生成更多文字补齐。
- 若比较与取舍已经顺畅，实际困难在交接，则重新评估图需方向。

## 6. 课堂与课后产出

**课堂：**老师示范一条判断链；学员完成配套练习，提出候选需求并为推荐项说明理由；老师补充或改变一个条件，检查学员能否调整判断。

**课后：**用模板整理一份需求清单。可以沿用桌麦案例，也可以使用自己的调研，但须标明真实证据、教学推导和待确认内容。

完成标准：能交付 **一条证据到判断的推导、2–3 条候选需求、一项推荐及理由、一个最关键的追问**。能回答“什么新证据会让我改选”，再进入 [Day 03：产品功能设计](<../3. prd/Day03产品功能设计.md>)。
