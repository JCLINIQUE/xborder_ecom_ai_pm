# Day 03｜课堂练习与功能清单模板

搭配 [产品功能设计教案](<Day03产品功能设计.md>) 使用。今天把 Day 02 的候选需求推进到具体功能与首版范围，不填写完整 PRD。

## 练习一：把“处理好资料”说具体

待修改的功能描述：

> 上传 Excel 和竞品链接，AI 自动处理文字和图片，生成最好的推广方案。

请改写成一组功能，回答：

1. 哪些资料需要关联到同一商品？链接没有读取成功时，当前实际拥有什么？
2. 提取哪些文字和图片信息，才能支持本次比较？
3. 比较结果与卖点建议分别长什么样？运营在哪里作出选择？
4. 首版只回答哪一个业务问题，哪些功能可以暂缓？

<details>
<summary>参考答案：从材料处理走到运营的决定</summary>

可以拆为 F1 资料整理、F2 图文信息提取、F3 竞品对照、F4 卖点建议与人工取舍。

- **F1：**按商品、规格和来源整理，标明实际取得的内容。链接未读到时，保留来源，提示补充文件或截图；不能把“有网址”当作“已读到内容”。
- **F2：**提取本次需要的产品特征、场景和图片表达，保留原文或画面位置；用已有工具汇总时注明来源。材料没有的信息保持未知。
- **F3：**输出自家与所选竞品的共同点、差异、依据和缺口。比较维度服务于当前场景，而不是复制所有字段。
- **F4：**提出候选卖点、适用人群与场景、理由和限制；运营能核查、修改或否定。不能承诺“最好”或直接推算销量。

首版可限定为一款自家商品与少量已选竞品，只分析卖点与图片表达。自动选品、完整市场报告、图需与生图不同时纳入。

</details>

## 练习二：让四项功能完成同一次任务

以下记录**全部为课堂模拟**，用于把桌麦案例中的分析方法变成可走查的功能样例；商品编号和记录不是原 Excel 中的竞品事实。此处图片以文字记录呈现，练习不代表已经实现或验证自动识图。

**任务：**运营希望为自家 S 选择面向移动办公场景的候选卖点。

| 来源编号 | 商品与课堂输入 |
| --- | --- |
| S-T | 自家 S 的已确认资料写明“支架可折叠”。未提供折叠后尺寸与重量。 |
| S-I | 自家 S 的图片记录：展示展开和折叠两种状态，未标注尺寸。 |
| A-T | 竞品 A 的页面文字写明“可折叠，便于收纳”。 |
| A-I | 竞品 A 的图片记录：展示产品折叠后的状态。 |
| B-I | 竞品 B 的图片记录：产品放在办公桌上；没有折叠状态或尺寸说明。 |
| C-L | 竞品 C 仅提供一个未能读取的链接，暂无文字或图片内容。 |

请交付一份小样：

1. F1、F2 输出的商品信息表，包含来源和未知项。
2. F3 的两条比较结论。
3. F4 的一条候选卖点、理由和限制，以及运营的一次取舍。
4. 如果业务方追加“直接生成图片”，说明本轮是否加入及理由。

<details>
<summary>参考输出与讲评</summary>

**F1、F2 的信息表：**

| 商品 | 当前支持的记录 | 依据 | 未知或缺口 |
| --- | --- | --- | --- |
| S | 资料明确可折叠，图片展示两种状态。 | S-T、S-I | 折叠后尺寸、重量、实际携带体验。 |
| A | 文案明确可折叠，图片展示折叠状态。 | A-T、A-I | 与 S 的尺寸、重量和体验差异。 |
| B | 当前图片展示桌面使用场景。 | B-I | 是否可折叠、是否适合携带。 |
| C | 只有来源链接，尚未取得商品内容。 | C-L | 商品文字和图片；需要补充材料。 |

**F3 的比较结论：**

- S 与 A 都有折叠相关资料，当前证据不支持“只有 S 可以折叠”或“S 更便携”。
- B 的图片未展示折叠状态，C 的内容未读取，均不能据此认定它们不具备折叠能力。

**F4 的候选及人工取舍：**

> 候选表达：可折叠收纳。依据为 S-T、S-I；本次面向移动办公场景，值得作为待讨论信息。限制是未验证携带体验，且 A 也有折叠特征，不能称为独有或最便携。
>
> 运营取舍示例：保留“可折叠”这一事实表达，暂不使用“比竞品更便携”；若要继续比较优势，补充相同口径的尺寸、重量及使用资料。

**范围判断：**本轮先输出有依据的对比和卖点取舍。图片生成需要进一步确认图需、素材与制作要求，列为后续候选；不能因为已能生成分析文字就认定可以直接交付商品图片。

此样例检查的是功能是否定义清楚，没有实际运行 AI，也没有证明新方案节省时间。老师可改变一个条件让学员重写结论，例如补充 B 的折叠资料，或发现自家参数有误。

</details>

## 课后：复制下面的功能设计模板

建议控制在 1–2 页，引用资料另附。功能编号自行确定，不必为了凑数量照抄 F1–F4。

### 1. 承接哪条需求

**Day 02 推荐需求：**［谁在什么场景，需要完成什么工作？］

**选择理由与依据：**［真实任务与材料位置；现有做法的不足。尚未确认的困难直接标明。］

**本课采用状态：**［真实任务已确认 / 课堂选定的候选，仍需确认哪些问题。］

### 2. 本次任务与首版范围

**用户要作出的决定：**［例如选定本次要表达的卖点。］

**输入范围：**［自家商品、所选竞品、场景、资料形式及实际可取得的内容。］

**最终输出：**［使用者拿到什么，接下来怎么用？］

### 3. 需求与功能对应表

| 对应需求 | 功能编号与名称 | 输入 | 产品完成什么处理 | 输出及人工决定 | 首版保留 / 暂缓及理由 |
| --- | --- | --- | --- | --- | --- |
| ［哪项用户需要］ | ［F1…］ | ［实际资料］ | ［具体动作］ | ［可见结果；哪里由人判断］ | ［为何必要或可以后做］ |
| ［哪项用户需要］ | ［F2…］ | ［实际资料］ | ［具体动作］ | ［可见结果；哪里由人判断］ | ［选择及理由］ |

### 4. 一组输入输出示例

**给定资料：**［列出几条真实摘录或明确标注的模拟记录，标明来源。］

**预期结果：**［写出具体对比或建议内容，不只写“生成成功”。］

**人工取舍：**［用户怎样核查、修改、接受或否定？］

**改变一个条件：**［例如竞品也具备该特征，或关键图片无法读取；结果应该怎样变化？］

### 5. 带入后续 PRD 的问题

［按本项目列出尚需明确的读取方式、AI 交互、资料更新、失败处理或验收问题。不在此处填未经学习或核对的技术架构。］

交卷前检查：每个功能能对应用户需要；输入实际可取得；结果有具体样例和依据；首版范围可解释；资料缺失与结论不成立时仍知道该怎样继续。
