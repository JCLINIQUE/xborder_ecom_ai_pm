# Day 03｜业务版 PRD 编写指南与示例

**这份材料用来把已推导出的功能写成可讨论、可走查的业务版 PRD。** 先看 [③ 一条需求怎样变成功能](<Day03产品功能设计.md>)，再读本页示例；[① 完整 PRD 模板](<PRD写作模板.md>)用于查看全貌和后续补充。

## 1. 为什么先写业务版

完整模板还包含 AI 交互、架构、路由、数据、评测与发布等内容。当前先把“帮助谁解决什么问题、产品怎样工作、做到什么程度”讨论清楚，可以避免在业务尚未明确时填入未经理解或验证的技术方案。

**业务版是同一份 PRD 的第一版。** 它保留用户问题、首版范围、功能与流程、关键规则、验收和待确认事项，先支持业务评审与原型设计。结果依据、缺失信息、失败后怎样继续、哪里由人决定，现在就要写清；具体页面状态、技术架构和评测方案随后补充。进入实现前，仍需补齐影响交付的细节并评审。

后续将本稿各段补入完整模板：背景／用户对应第 1、4 章，范围对应第 2 章，功能与规则对应第 7 章，验收对应第 14 章，未知对应第 16 章；再逐步补交互、架构、数据和评测。保留已确认的功能编号与业务规则，随新证据修订。

## 2. 业务版写哪些内容

| 部分 | 必须回答 |
| --- | --- |
| 用户与问题 | 谁在什么场景遇到什么困难？证据和假设分别是什么？ |
| 目标与范围 | 本次帮助用户完成什么？首版处理到哪里？ |
| 流程与功能 | 用户如何开始、产品处理什么、输出什么、人在哪里决定？ |
| 关键规则 | 什么能比较？缺信息、处理失败或证据变化时怎样继续？ |
| 验收与待确认 | 用什么输入检查预期行为？还缺什么业务证据和设计决定？ |

下面用③推导出的同一条需求和 F1–F4 演示成文。**③解释功能为什么这样拆，本页说明这些功能应怎样表现。**

## 3. 示例｜竞品跟踪决策助手 · 业务版 PRD

版本：课堂业务草案 v0.1｜状态：需求与方案待验证｜案例：Day 02 的价格／促销事件

### 用户与问题

**用户：**持续跟踪指定竞品的亚马逊运营。

**需求：**运营需要从可信的价格／促销变化中，结合自家情况明确关注理由与处理方向，以便决定跟进、观察或忽略。

[调研报告](<../1. user-research/用户调研报告-亚马逊精品运营-20260914.md>)提供了工具漏抓、人工核验及结合自家情况判断的线索。当前哪些步骤最费力、真实频率和代价仍待回溯。本示例复用 [Day 02 案例①](<../2. product-sense/Day02课堂练习与参考答案.md#case-price>)的 A-1、A-1-I、A-2、S-1/2；这些数据均为教学模拟。

### 目标与首版范围

**目标：**帮助运营从一条竞品变化走到有依据的处理决定，减少无方向核查；实际提效需后续测量。

**首版：**一款自家商品、一款指定竞品、一次价格／促销事件。复用已有工具记录，允许补充截图或人工核对结果。产出为“变化事件＋关注理由与待核查项＋运营决定”。

**暂不包含：**新建爬虫、全量自动监控、自动调价／投放，以及改图、流量、差评等其他事件类型。课堂数量用于控制范围，不代表真实运营工作量。

### 用户流程与功能

运营提供前后记录 → 核验并补充信息 → 查看变化及判断摘要 → 决定跟进、观察或忽略 → 记录理由和后续事项。

| 功能 | 输入与处理 | 用户得到什么 |
| --- | --- | --- |
| **F1 关联并核验跟踪记录** | 接收带时间、站点、ASIN／变体、卖家与来源的记录；关联同一商品与卖家的报价，提示口径差异和缺失项，支持补充与修正。 | 已知记录、出处及具体缺口。资料存在不代表事实已经核实。 |
| **F2 识别价格／促销变化** | 比较可对应记录中的标价、优惠及已知条件；区分字段未采集、页面未展示和已观察到变化。 | 带前后依据的变化事件；证据不足时列待核查。 |
| **F3 辅助排查与处理判断** | 结合变化事件、自家经营资料与动作约束，整理关注理由、优先核查项和有条件的处理方向；区分事实与可能解释。 | 可核查、可修改的判断摘要，支持用户取舍。 |
| **F4 记录运营决定** | 运营选择跟进、观察或忽略，填写理由及后续事项；保存本次决定，允许补证后修订。 | 与所依据材料关联的决定记录。该操作不触发调价或投放。 |

F4 让本次任务有明确结果；长期回看、提醒与多人协作的需要仍待调查。

### 关键业务规则

1. **先对齐记录。** 时间和来源需明确；不同站点、商品变体、卖家或价格口径不直接混成同一次报价变化。缺项可保留，只阻止依赖该信息的确定判断。
2. **计算保留条件。** 本例标价均为 11,800 日元。旧券字段未采集时不能认定新增优惠；补 A-1-I 后可确认两个时点优惠展示不同。若 2,000 日元券适用，条件计算为 9,800，比自家标价 10,800 低 1,000；须同时标注资格未知，不能称为所有买家的实际成交价。
3. **判断与动作分开。** 缺少自家经营数据时可给核查方向，不能声称竞品抢走销量或要求跟价。有依据的观察、忽略也是有效决定。
4. **保留人工控制。** F3 的建议须能回查依据，运营可修改或拒绝；处理失败时保留已有记录和人工内容，允许手动继续。结果若由模拟生成，必须标明。
5. **证据更新后复核。** 重算受影响的变化与摘要；保留原决定和人工修改，标明依据已变化，提示运营复核后更新，不能静默覆盖或继续显示为已确认。

### 一组输入输出与验收

沿用 Day 02 原促销事件，不使用它的“已确认直接降价”替换条件。以下为预期行为，尚未实施测试。

| 检查 | 给定输入与操作 | 预期结果 |
| --- | --- | --- |
| 核验与识别 · F1/F2 | 查看 A-1、A-2，再补 A-1-I。 | 补证前仅确认本次展示券；补证后确认两个时点优惠展示不同，标价未变。各结论可找到对应记录。 |
| 判断支持 · F3 | 加入 S-1/2，自家经营数据仍缺失。 | 摘要说明有条件的价格位置变化，优先核实券资格、期限及自家相关数据；不输出确定归因或自动跟价指令。 |
| 运营决定 · F4 | 选择“跟进”，写明先补券条件与自家经营资料。 | 保存决定、依据、理由与待办；不执行任何经营调整。 |
| 证据不足与变更 · F1–F4 | 撤去 A-1-I，只保留旧券字段未采集的记录。 | 撤回“两个时点优惠展示不同”的确定结论，标出需补旧记录；保留人工内容，提示原决定需复核。 |

### 待确认与后续补充

**业务：**回溯一次行动和一次未行动的真实案例；测量现有工具辅助下的核验、判断及修改成本，确认方案是否减少总人工负担。

**设计：**后续补导入与识读方式、结果调整和确认状态、保存方式、模型与架构、质量评测。当前规则用于约束这些设计，尚不足以直接替代完整交付规格。

## 4. 学员怎么使用

参照示例的五部分，为自己在 Day 02 选定的需求写一份 **2–3 页业务版 PRD 初稿**。需求与功能推导引用③或自己的推导记录，材料用链接引用；在功能段写明确的输入、处理、输出，在验收段至少给一条正常路径和一条缺信息的情况。当天交这一份初稿，待确认问题随稿保留。
