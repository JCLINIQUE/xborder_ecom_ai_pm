# Day 03 示范｜一条需求怎样变成产品功能

先浏览 [PRD 写作模板](<PRD写作模板.md>) 了解全貌，再看本示范，最后按 [业务版 PRD 编写指南](<Day03业务版PRD编写指南.md>) 写初稿。**本课交付业务版 PRD 初稿；这里示范的是写之前怎样推导功能。**

沿用 [Day 02 案例①：看到竞品降价／促销](<../2. product-sense/Day02课堂练习与参考答案.md#case-price>)，不另换场景。A-1、A-1-I、A-2、S-1/2 均为教学模拟；真实连续记录与完整决策案例仍待补充。

## 1. 从用户要作出的决定往前推

产品暂称**竞品跟踪决策助手**，承接的需求是：

> 运营需要从可信的价格／促销变化中，结合自家情况明确关注理由与处理方向，以便决定跟进、观察或忽略。

先不写“上传、分析、导出”这些功能名。老师沿着“运营怎样才能作决定”逐步追问：

1. **能相信这条信号吗？** 要找到前后记录，确认是同站点、同 ASIN／变体、同卖家的报价；字段没采到与实际没有优惠要分清。
2. **具体变了什么？** 要分别比较标价、券和适用条件，知道证据支持哪句话、哪些仍未知。
3. **为什么值得我关注？** 要看它可能怎样改变价格位置，再结合自家经营情况、目标和动作约束判断；缺什么资料就先排查什么。
4. **这次准备怎么处理？** 要选择跟进、观察或忽略，说清理由及下一步。

这四步是为了完成业务目标而需要的工作。功能应承接这些工作，不能仅因 AI 能生成文字就加入“自动建议”。

## 2. 再决定哪些工作交给产品

先划分责任，再给功能命名：

- **现有工具复用：**提供已有采集记录、经营数据或截图。这里不重新建设采集系统。
- **本产品负责：**关联记录、发现口径与证据缺口、展示变化，并把与本次判断有关的依据和处理条件整理清楚。
- **运营确认：**核对关键事实，补充自家目标和约束，决定是否采取动作。信息不够时，继续核查也是有效决定。

据此得到下面的功能。老师逐行说明它解决了上面哪一步，以及删掉它后运营还要自己做什么。

| 推导出的功能 | 具体承接的工作与结果 |
| --- | --- |
| **F1 关联并核验跟踪记录** | 接收已有记录与补充证据，按商品、卖家、时点和价格口径关联，输出可比较记录与待核查项。 |
| **F2 识别价格／促销变化** | 用可对应的前后记录区分标价与优惠变化，输出带来源的变化事件；证据不足时说明无法确认什么。 |
| **F3 辅助排查与处理判断** | 结合变化事件与自家情况，输出关注理由、优先核查项、可选处理方向及成立条件。 |
| **F4 记录运营决定** | 接收运营的选择与理由，保留本次决定及后续事项，让任务有明确结果。 |

F4 是本次课堂流程的基础支持；“长期回看很困难、必须做提醒与协作系统”尚无证据，不由此扩展需求。

## 3. 把 F3 写到能看见结果

“辅助运营判断”仍太笼统。拿 Day 02 的输入，要求它给出具体内容。

**输入：**A-1、A-2 的标价均为 11,800 日元；A-1-I 未展示券，A-2 展示 2,000 日元券，资格和期限未知。S-1/2 的自家标价为 10,800，缺同期经营数据与动作约束。F1、F2 已确认的是两次页面优惠展示不同。

**F3 应输出：**

> **关注理由：**若该券适用且两款商品适合比较，按标价减券面额计算为 9,800 日元，比自家标价低 1,000。这是继续排查的线索，不是已核实的普遍成交价。
>
> **优先核查：**先确认券影响哪些买家、有效到何时，再补自家同期销量、转化、广告及利润等相关约束。
>
> **处理方向：**可先跟进核查；资料暂时拿不到时，可观察并写明等待什么信息。信息齐备后，再比较是否采取价格或促销动作。
>
> **判断边界：**没有依据断言竞品在清库存、抢走了自家销量，也不足以直接给出跟价方案。

这份输出交给 F4。运营例如选择“跟进”，并记录“先核券资格，再补自家经营背景”。产品提出判断依据与方向，运营完成取舍。

## 4. 缺一份证据，功能怎样变化

撤去 A-1-I，只剩旧工具字段“未采集”。此时 F1 标出缺口，F2 不能再确认新增优惠或前后展示变化，只能确认本次展示了券。

F3 仍可指出本次优惠值得核实，但第一步应改为“先查旧页面，分清变化与漏采”。F4 保留原选择与理由，标记依据已变化，提示运营复核后更新。**同一个按钮选择不代表同一个判断，功能要反映依据怎样改变结果。**

## 5. 选首版，再写业务版 PRD

首版只走通**一款自家商品、一款指定竞品、一次价格／促销事件**。保留 F1–F4 的最小流程：F1、F2 提供可信输入，F3 支持排查与处理判断，F4 形成一次人工决定。

复用已有记录，允许补充证据；不新建爬虫、不自动跟价。经营系统集成、定时提醒与长期协作后置，避免把一次判断扩成整套运营平台。
