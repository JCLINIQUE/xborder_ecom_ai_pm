# Day 03｜产品功能设计：从需求到首版功能清单

**今天交付：需求与功能对应表、首版范围、一组完整的输入输出示例。** Day 02 解释用户需要什么、依据是什么；Day 03 继续回答产品提供什么功能，以及用户如何用它完成任务。功能明确后再写 PRD。

材料：[Day 02 课件](<../2. product-sense/Day02产品需求提炼.md>) · [需求清单](<../2. product-sense/产品需求清单模板.md>) · [用户调研报告](<../1. user-research/用户调研报告-亚马逊精品运营-20260914.md>) · [课堂练习与功能清单模板](<Day03课堂练习与功能清单模板.md>)

## 1. 承接哪条需求

本课承接运营的**日常竞品跟踪与运营判断**，课堂首版聚焦价格／促销变化：

> 运营每天查看已关注的竞品时，需要确认价格或促销发生了什么变化，再结合自家经营情况，决定是否跟进、继续观察或忽略，并知道还要核实什么。

课堂产品暂称**竞品跟踪决策助手**。已有采集工具提供部分记录，产品先复用这些结果。真实的连续快照与完整决策案例目前尚未取得；具体困难、频率和改进价值仍需验证，下面的功能是待验证的设计方案。

产品要回答：**这次变化是否可信、与自家是否相关、运营下一步准备做什么？** 选品阶段的市场调研属于另一条任务，不能用静态市场报告代替日常跟踪记录。

## 2. 从需求拆出四项功能

主流程：**提供已有记录 → 核对变化 → 补齐判断背景 → 运营决定与记录。**

| 编号与产品功能 | 输入 | 产品做什么 | 输出 |
| --- | --- | --- | --- |
| **F1 关联并核验跟踪记录** | 现有工具导出、页面截图或人工核对记录，包含时间、站点、ASIN／变体、卖家及来源。 | 关联同一商品与卖家的报价，核对价格口径，标出缺失、读取失败或待核验内容，允许补充。 | 可用于比较的记录及具体缺口。 |
| **F2 识别价格／促销变化** | 同一竞品不同时点、口径可对应的记录。 | 分别比较页面标价、优惠券及已知条件，保留前后证据；无法确认的变化列为待核查。 | 变化事件：何时看到什么变化、依据是什么、哪些仍未知。 |
| **F3 辅助排查与处理判断** | 变化事件，以及运营提供的相关时段自家销量、转化、广告等资料与动作约束。 | 说明为什么值得关注，列出优先核查项和有条件的处理方向；区分事实、可能解释与未知，资料充分后才比较具体运营动作。 | 判断摘要：关注理由、依据与缺口、可选方向及成立条件。 |
| **F4 记录运营决定** | 判断摘要与运营判断。 | 支持选择跟进、观察或忽略，记录理由、待办或下次查看条件；补充证据后可更新决定。 | 带依据、理由和后续事项的决定记录。 |

F1、F2 帮运营确认“发生了什么”；F3、F4 支持“接下来怎么办”。F4 是让本次任务形成明确结果的基础支持，是否需要长期回看、提醒或协作管理仍待调查。

**缺记录不等于没变化；自家指标同期下降，也不能证明是竞品促销导致。** 系统整理依据和核查线索，调价、投放等决定由运营掌握。

## 3. 用一个变化事件检验功能

以下接续 Day 02 的**虚构课堂示例**，不是已取得的真实连续快照，也不是市场报告中的记录：

> 日本站同一 ASIN／变体、同一卖家的两条记录，页面标价均为 11,800 日元。旧工具记录未采集优惠券字段；补查旧截图后，确认旧页面未展示券，本次页面展示 2,000 日元券。适用资格与期限仍未知。自家对应商品标价为 10,800 日元，暂缺同期经营数据和动作约束。

- **F1：**关联工具记录与补充截图，保留时间和来源；旧字段“未采集”与截图“未展示券”分别记录，不能混成一回事。
- **F2：**输出“两个记录时点页面的优惠展示不同，标价未变”。不能写成“标价降了 2,000 日元”或“所有买家都能用券”。
- **F3：**说明“若券适用且商品适合比较，竞品有条件价格会低于自家标价，值得继续排查”；优先核实券资格，再结合自家数据评估后续动作。不能在没有证据时写“竞品抢走销量，应跟降”。
- **F4：**运营可以决定先跟进核查，写明原因与下一步；也可以在依据充分时选择观察或忽略。

如果今天的记录没有取得，F2 应输出“无法确认今天是否变化”，而不是把昨天的数据当作今天的状态。完整输入与参考输出见配套练习。

## 4. 确定首版范围

教学首版围绕**一款自家商品、一款已关注竞品、一次价格／促销变化事件**完成流程。数量用于限制练习规模，不代表真实运营的跟踪量。

| 首版选择 | 理由 |
| --- | --- |
| **保留 F1–F4 的最小流程。** | 只有变化清单，运营仍不知道要查什么、如何继续；本次练习需走到一次有理由的人工决定。 |
| **复用已有采集记录，允许补截图或人工核验。** | 先验证采集之后的工作，首版不建设爬虫或新的定时采集系统。链接仅作来源时，不表示系统已读到页面。 |
| **F3 先接收与本次事件有关的自家资料。** 不强求所有指标齐全，也不接入全套经营系统。 | 只补判断所需的信息；信息不足时保留待核查状态，不编造归因或收益。 |
| **保存本次决定及后续查看事项。** | 支持补记录后继续核查；自动提醒和复杂任务管理可后置，实际回看需要仍待验证。 |

本期不做选品市场分析、卖点生成、图需，也不自动执行调价或投放。首版产出是**变化事件＋判断背景与缺口＋运营决定**。后续要用真实事件比较现有流程与本方案的核查成本和结果可用性，不能预填节省时间。

## 5. 课堂与课后怎么做

- **老师示范：**用上述事件说明“发现变化”“判断影响”“采取动作”是不同步骤，再对应到 F1–F4。
- **学员练习：**完成配套样例，分别处理资料齐全、记录缺失和只有同期相关性的情况，说明首版取舍。
- **课后产出：**使用模板完成一份功能设计和输入输出样例。有真实连续记录时注明出处；没有时继续使用明确标注的模拟材料。

完成时应能说明：每项功能支持哪条用户需要、输入从哪里来、结果具体是什么、哪些判断由人完成。

## 6. 下一步怎样进入 PRD

将确认后的功能清单带入 [PRD 写作模板](<PRD写作模板.md>)，再展开操作流程、AI 交互、记录更新、异常处理与验收。尚未学习或确定的实现列为待补问题，不提前把架构作为本课交付。
