# Day 03｜产品功能设计：从需求到首版功能清单

**今天交付：需求与功能对应表、首版范围、一组完整的输入输出示例。** Day 02 解释用户需要什么、依据是什么；Day 03 继续回答产品提供什么功能，以及用户如何用这些功能完成任务。功能明确后再写 PRD。

材料：[Day 02 课件](<../2. product-sense/Day02产品需求提炼.md>) · [需求清单](<../2. product-sense/产品需求清单模板.md>) · [桌麦市场调研](<../5. demo/桌麦市场调研.xlsx>) · [课堂练习与功能清单模板](<Day03课堂练习与功能清单模板.md>)

## 1. 承接哪条需求

Day 02 可以提出资料整合、辅助分析、图需交接等候选。本课选择**辅助竞品分析与卖点选择**作为功能设计案例：

> 亚马逊精品运营准备商品推广时，需要结合自家商品和选定竞品的资料，比较产品特征、用户场景与图片表达，选择有依据的主打卖点。

课堂产品暂称**竞品资料分析助手**。这次选择有真实工作样本可供拆解；当前最费力的步骤、现有工具的剩余缺口和可改善的代价，仍需接着 Day 02 的问题确认。选择教学案例不等于已证明值得开发。

产品要回答一个具体问题：**在本次选定场景和竞品范围内，自家商品应该优先表达什么，依据是否充分？**

## 2. 从需求拆出四项功能

主流程：**提供资料 → 提取商品信息 → 自家与竞品对照 → 查看卖点建议 → 运营修改、取舍。**

| 编号与产品功能 | 输入 | 产品做什么 | 输出 |
| --- | --- | --- | --- |
| **F1 导入并整理资料** | 自家参数、工具导出表、商品文字、图片或链接。 | 将资料关联到对应商品和规格，记录来源与读取状态；提示缺少或无法读取的材料，允许补充。 | 按商品整理的资料集。 |
| **F2 提取文本与图片信息** | F1 中已取得的文字、表格和图片；已有工具分析可直接作为材料。 | 提取参数、宣称的卖点、使用场景和图片表达内容；区分原文、画面观察与分析推测，并关联出处，供运营修正。 | 可回查的商品信息表。 |
| **F3 生成自家与竞品对照** | 已核对的信息、本次分析场景与比较维度。 | 对照产品特征、适用场景和图片表达，指出共同点、差异与信息不足；说明哪些资料不能用于当前判断。 | 带依据的对比结果。 |
| **F4 提出卖点建议并支持取舍** | F3 的结果及已确认的自家事实。 | 给出少量候选，说明面向谁、适合什么场景、支持理由和限制；允许运营接受、修改或否定并记录理由。 | 卖点候选、运营的选择及待确认事项。 |

F1、F2 准备可用资料；F3、F4 帮助运营完成比较与选择。若输入已经包含人工确认好的卖点，产品只负责扩写图需，就跳过了本课要设计的分析工作。

“AI 分析一下”“生成报告”都还不足以定义功能。学员要说清：比较哪些信息、输出哪些判断、用户如何检查和继续使用。修改、保存和导出服务于上述任务，不单独当作核心业务价值。

## 3. 用桌麦报告理解功能应该做到哪里

报告提供了以下真实材料位置：

| 材料 | 可以拿来讨论什么 |
| --- | --- |
| 《产品特征提取》C19:C28 | 报告记录的折叠、收纳、会议等特征和场景，分别需要什么来源支持。 |
| 《直接竞品对比分析（日本版）》C10、C15 | 作者如何提出便携、视频会议、桌面整洁等定位。 |
| 《评论分析》A5:C9、E5:G9 及相应截图 | 哪些内容已有工具汇总，可以复用；样本口径仍需核对。 |
| 《调研结论》A1 | 作者最终提出的定位与图片方向，作为回溯参考。 |

先选定自家商品并核实其资料。报告中的不同商品、不同站点材料不能混成一款自家商品的事实，报告作者的判断也需要检查依据。

下面是**功能设计示例，并非实测产品输出**：

> 输入中，自家资料确认“可以折叠”；竞品 A 的资料也明确写了“可折叠”。
>
> **F2：**分别提取两款商品的折叠特征，附各自来源。
>
> **F3：**说明两者都具备这一特征；仅凭当前资料不能认定自家在便携性上更强。
>
> **F4：**可将“便于收纳”列为候选表达信息，但不称为独有优势。若要进一步比较，列出需补充的收纳尺寸、重量或实际使用资料，交由运营决定是否继续研究。

**功能要允许得出“目前没有足够证据支持差异化卖点”。** 不能为了给出建议，把竞品未提及写成竞品不具备，把图片中出现的场景写成已验证的用户偏好。

## 4. 确定首版范围

教学首版可选**一款自家商品、三款人工选定的竞品、一个使用场景**。数量用于限制练习规模，不代表真实运营的工作量。

| 首版选择 | 理由 |
| --- | --- |
| **保留 F1–F4，完成一次分析。** 使用选定工作表、相关商品文字与图片，不要求读完整本市场报告。 | 从资料走到卖点选择，才能检查产品是否支持了核心任务。 |
| **支持补充文件、图片或截图。** 链接需区分“内容已读取”和“仅记录来源”；无法取得内容时提示补充。 | 提供网址不等于系统已经看过文字和图片，缺少材料时仍要能继续整理。 |
| **先复用现有工具输出。** 提取与对照围绕当前任务，只补剩余能力。 | 报告已经使用工具分析，不能把全部处理都设计成从零重做。 |
| **图需整理、自动生图、全市场趋势、利润测算、自动发现竞品和持续监控暂缓。** | 它们需要额外输入或服务其他决定；本轮先完成有依据的比较与卖点选择。 |

首版输出是**竞品对比结果＋卖点候选及理由＋运营取舍＋待确认事项**。现有做法与新方案的总人工时间、结果能否用于工作，需要后续用同一任务比较，不在本课预填收益。

## 5. 课堂与课后怎么做

- **老师示范：**从桌麦报告的一条判断，推到 F2、F3、F4 各自应该提供什么；重点讲清“资料提取”和“业务判断”的区别。
- **学员练习：**用配套样例写出功能输入、处理和输出，选择首版范围；分别处理“竞品也有该特征”和“资料缺失”两种情况。
- **课堂讨论：**追问每项功能支持哪条需求，删除不能帮助当前任务的功能，补齐无法解释的输出。
- **课后产出：**使用配套模板完成一份功能设计。可以继续桌麦案例；迁移到自己的场景时，保留相同的需求推导方法。

完成时应能说明：每项功能为什么需要，用户提供什么，结果是什么样，哪些结论要由人确认，以及首版为什么取舍这些功能。

## 6. 下一步怎样进入 PRD

将确认后的功能清单带入 [PRD 写作模板](<PRD写作模板.md>)，再展开操作流程、AI 交互、读取与识图方式、异常处理和验收要求。尚未学习或确定的实现写成待补问题。

Day 03 的功能设计不是完整 PRD，也不是已实现的产品。后续原型和 Demo 应承接新功能设计补齐 PRD；仓库原有 SSD PRD 与原型保留作旧版写法参考，不直接套用其中的价格规则或 R1–R4 编号。
